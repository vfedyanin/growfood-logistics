# Текущий контекст — bald-logist

Обновлено: 06.08.2026

## Над чем идём

**Автоматическое распределение плеч по рейсам.** Работа не начата: в коде нет ни
функции, ни ветки, ни незакоммиченных изменений. Есть только ручные операции.

### Что уже есть в коде (ручное распределение)

`src/lib/actions/requests.ts`:
- `addCargoLegToTrip(legId, tripId)` — привязать плечо к рейсу; создаёт
  `TripCargoUnit` и подтягивает `plannedDeparture` / `plannedArrival` рейса по
  датам плеча
- `createTripFromLeg(legId)` — рейс из одного плеча
- `createTripFromRequest(requestId)` — рейс и все непривязанные плечи заявки в него
- `getUnassignedCargoLegOptions({ directionId, date })` — кандидаты на привязку,
  фильтр по направлению и дню забора
- `unassignCargoLeg(legId)` — открепить

Точка входа для оператора: страница «Груз» (`operations/cargo`), открывается с
фильтрами «Забор — завтра» + «Без рейса».

## Ограничения схемы, влияющие на задачу

- `RequestCargoLeg.tripCargoUnitId` — `@unique`. Плечо и грузовая единица
  связаны строго 1:1, разделить одно плечо между двумя машинами нельзя без
  миграции.
- `VehicleType.capacityPallets` в схеме есть, но в
  `src/app/(protected)/operations/trips/page.tsx:123` вместимость парсится
  регуляркой `/VT-(\d+)/` из кода типа ТС. Либо поле не заполнено, либо про него
  забыли — проверить перед тем, как опираться на вместимость.
- У `Direction` нет поля перевозчика. В бэклоге названо блокером автоназначения
  рейсов. В таблицах пользователя перевозчик стоит в шапке направления (РТК,
  ИП Сенькова, Трансхолод-НН, МобиГрупп, ИП Мерзликин).
